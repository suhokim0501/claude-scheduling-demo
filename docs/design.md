# 설계와 구현 상세

[프로젝트 소개로 돌아가기](../README.md)

이 문서는 실제 구현의 역할과 데이터 흐름을 설명합니다. 회사 소스코드, 실제 병원 자료와 내부 운영 수치는 포함하지 않았습니다.

## 기존 엔진을 도구로 연결

기존 최적화 모델과 결과 평가·출력 기능을 MCP 서버에서 호출하도록 구성했습니다. MCP 클라이언트가 도구를 선택해 인자를 전달하면, 서버는 해당 기능을 실행하고 구조화된 결과를 반환합니다.

별도의 Claude API 호출을 서버에 넣는 대신, Claude Desktop을 MCP 클라이언트로 활용하는 형태입니다. 검토한 구현의 전송 방식은 stdio입니다.

| 계층 | 입력 | 수행 작업 | 반환 내용 |
|---|---|---|---|
| MCP 클라이언트 | 사용자 요청 | 도구 선택, 인자 구성, 결과 설명 | 사용자에게 필요한 안내 |
| 입력·설정 도구 | 기간, 파일, 변경 요청 | 날짜 확인, 파싱 검증, 설정 조회·변경 | 검증 결과, 변경 전후 값 |
| 생성 도구 | 데이터와 현재 설정 | 입력 객체 구성, 기존 엔진 실행 | 성공 여부, 결과 ID, 시간 정보 |
| 분석·비교 도구 | 결과 ID | 기존 평가 함수 호출, 분석 결과 비교 | 지표, 차이, 다음 검토 사항 |
| 질의·출력 도구 | 결과 ID와 요청 | 표 변환·집계, 기존 출력 함수 호출 | 질의 결과 또는 파일 정보 |

## 설정 처리

### 가중치

설정 이름과 설명의 키워드를 이용해 대상 조건을 찾고, 지원하는 표현을 중요도 단계에 매핑합니다. 따라서 자연어 설정 도구 자체가 별도의 학습 모델로 문장을 이해하는 방식은 아닙니다.

모호한 요청에서 잘못된 조건을 선택하지 않도록 하려면, 실제 변경 대상을 사용자에게 확인하고 변경 전후 값을 보여주는 절차를 보강할 필요가 있습니다.

### 제약 기준

기존 모델이 제공하는 설정 항목에 대해 명시적인 숫자 값을 전달받아 수정합니다. 사용자가 임의의 문장으로 새로운 수학적 제약을 추가하는 기능과는 구분됩니다.

### 탐색시간

지원하는 문구와 시간 표현을 초 단위 설정으로 변환합니다. 탐색시간을 늘리는 것은 더 좋은 결과를 찾을 기회를 늘리는 설정이며, 특정 품질 향상을 보장하는 기능으로 설명하지 않습니다.

### 기본값 보완

서버에 보관한 현재 설정과 기본값을 병합해 일부 항목 누락을 보완합니다. 별도 설정을 직접 전달하는 경우까지 모든 입력 조합에서 같은 보완이 이루어지는 것은 아니므로, 후속 구현에서는 설정 검증을 공통 단계로 정리할 필요가 있습니다.

## 생성 결과와 분석 결과 관리

생성 도구는 다음 정보를 결과 ID와 함께 메모리에 보관합니다.

- 생성된 근무표와 사용한 입력 객체
- 가중치와 제약 기준
- 입력 구성과 엔진 실행의 소요시간
- 생성 시각

분석 결과는 같은 ID를 기준으로 별도로 저장합니다. 비교 도구는 두 결과의 분석 정보가 준비되었는지 먼저 확인하고, 없으면 분석을 수행하도록 안내합니다.

이 구조는 조건을 바꾸어 새 결과를 생성하더라도 이전 결과를 함께 조회할 수 있게 합니다. 다만 영속 저장이나 사용자별 세션 분리가 갖춰진 운영 서비스는 아닙니다.

## 근무표 데이터 질의

생성된 근무표를 사람·날짜 단위의 긴 형태로 변환하여 pandas로 처리합니다. 근무코드와 요일 등의 열을 제공하므로 근무 횟수 집계나 특정 날짜의 배정 조회 같은 후속 질의가 가능합니다.

입력 파일의 근무코드 정보도 별도로 캐시해 질의 결과를 해석할 수 있도록 했습니다. 이 변환·질의 기능과 이후 근무코드 정보 제공 개선은 제가 직접 추가한 부분입니다.

시제품은 전달된 Python 표현식을 실행하는 방식이므로, 운영 서비스에서는 실행 환경과 권한을 분리하거나 허용된 집계 기능만 제공하는 방식으로 개선할 필요가 있습니다.

## 분석·비교 결과의 해석

분석 도구는 기존 엔진의 평가 결과를 가공하고, 비교 도구는 분석 결과의 점수·지표 차이를 정리합니다. 서버가 만든 요약 점수와 최적화 엔진의 목적함수 값은 별개입니다.

일부 개선 제안은 사전에 정한 규칙에 따라 생성됩니다. AI가 원인을 검증하거나 설정 변경의 효과를 인과적으로 입증한 결과로 해석하지 않습니다. 필수 조건의 검증 역시 보고서 문구와 별도로 확인해야 합니다.
