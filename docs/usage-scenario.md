# 대표 사용 시나리오

[프로젝트 소개로 돌아가기](../README.md)

아래 문장과 순서는 구현 기능을 설명하기 위해 구성한 예시입니다. 실제 사용자 대화, 병원 입력 데이터, 측정 결과를 재현한 자료는 아닙니다. 숫자로 된 배정 결과나 성능 수치는 예시로 만들어 넣지 않았습니다.

## 1. 기간과 입력 확인

**사용자 요청 예시**

> 다음 달 근무표를 만들고 싶어. 필요한 데이터를 알려줘.

클라이언트는 구체적인 시작일·종료일을 확인해 기간 설정 도구를 호출하고, 필요한 엑셀 시트 구조를 안내합니다. 입력 파일을 전달받으면 기존 파서로 데이터를 읽을 수 있는지 검증합니다.

**확인할 내용:** 날짜, 파일 존재 여부, 파싱 오류. 검증이 끝난 뒤에는 현재 설정을 조회하도록 안내합니다.

## 2. 조건을 검토하고 근무표 생성

**사용자 요청 예시**

> 현재 설정을 보여줘. 확인한 조건으로 근무표를 생성해줘.

현재 가중치·제약 기준·탐색시간을 조회하고, 생성 도구가 입력과 설정을 기존 최적화 엔진에 전달합니다. 해를 얻으면 결과 ID를 부여해 근무표와 사용한 설정을 저장합니다.

**확인할 내용:** 생성 성공 여부, 결과 ID, 소요시간. 이 단계의 성공을 사용자가 최종 승인한 근무표나 상용 운영 결과로 표현하지 않습니다.

## 3. 결과를 분석하고 질의

**사용자 요청 예시**

> 신청 근무가 얼마나 반영됐는지 확인하고, 개인별 야간근무 횟수를 비교해줘.

분석 도구로 기존 평가 지표를 조회하고, 추가 집계가 필요하면 근무표를 표 형태로 변환해 질의합니다. 클라이언트는 반환된 결과를 바탕으로 사용자에게 설명합니다.

**확인할 내용:** 어떤 지표를 조회했는지, 어떤 집계 기준으로 계산했는지. 보고서의 요약 점수만으로 모든 운영 조건을 검증했다고 판단하지 않습니다.

## 4. 조건 수정 후 재생성·비교

**사용자 요청 예시**

> 야간근무 횟수 균등화를 더 중요하게 해줘. 다시 생성해서 이전 결과와 비교해줘.

지원하는 설정 표현에 따라 변경 대상을 찾고 가중치를 조정합니다. 변경 결과를 확인한 뒤 새 근무표를 생성합니다. 두 결과를 각각 분석한 상태에서 비교 도구를 호출합니다.

**확인할 내용:** 변경한 설정, 이전·새 결과 ID, 개선되거나 나빠진 지표. 특정 조건의 가중치를 높였다고 모든 지표가 동시에 좋아지는 것은 아닙니다.

## 5. 결과 출력

**사용자 요청 예시**

> 비교한 결과 중 선택한 근무표를 엑셀과 HTML 보고서로 저장해줘.

선택한 결과 ID를 명시해 출력 도구를 호출합니다. 서버는 기존 출력 함수를 이용해 파일을 만들고 저장 위치 등의 정보를 반환합니다.

**확인할 내용:** 출력한 결과 ID와 파일 정보. 실제 병원 자료가 담긴 파일은 이 포트폴리오에 포함하지 않았습니다.
